# 可扩展强化学习教学实验方法

## 目标

这个项目是 [RL Field Guide](https://ssx86.github.io/rl-field-guide/en/) 的可运行配套实验，不把“能跑算法”当作教学完成。学习者必须能够从界面证据解释一次更新、一个策略和一段训练历史。每个实验都沿用教程的同一条闭环：

```text
先预测 → 再运行 → 检查真实数值 → 用公式解释 → 改变假设做迁移
```

四个当前实验与教程章节的精确映射、前置知识和边界统一登记在 `src/catalog/experiment-catalog.ts`，架构约束见 `docs/TUTORIAL_COMPANION_ARCHITECTURE.md`。界面不得自行维护第二份算法定义或教程链接。

## 四层技术边界

### 1. 环境层

负责状态、动作、奖励、终止条件和可解释事件。环境返回的不只是 reward，还返回 `event`、`collision` 与 `fell`，这样界面能解释“为什么得到这个奖励”。环境层不得知道 Q 表或具体算法。

### 2. 策略层

负责从价值表示中选择动作，并显式标注动作来自探索还是利用。后续 Expected SARSA 需要在这一层增加动作概率分布，但不能把概率计算藏进 UI。

### 3. 更新层

负责把一次 transition 转成新的价值，并返回教学中间量。统一代码契约位于 `src/domain/learning-strategy.ts`。每个策略接收环境 transition、Q 表、超参数与确定性随机源，返回新价值、TD 数据和算法独有的 `signals`。Q-learning 当前返回 `bootstrap`、`target` 与 `tdError`；SARSA 应增加 `nextAction`，Double Q-learning 应标明被读取和被更新的表，Dyna-Q 应标明样本来自真实环境还是模型规划。

### 4. 证据层

负责呈现而不重新计算算法：当前步骤看因果，地图层看空间结构，回合记录和曲线看长期变化。所有可视化都必须读取同一条训练事件流，避免界面与算法各自计算出两套结果。

## 新算法接入模板

1. 在 `src/catalog/experiment-catalog.ts` 登记实验、教程章节、预测题、运行指令、证据、公式、迁移问题和 `requiredSignals`。
2. 实现 `LearningStrategy`，定义更新语义与中间量，不直接复制 Q-learning 的字段。
3. 为单步 target、终止状态、边界碰撞和确定性动作选择编写测试。
4. 在状态观察器中展示该算法独有的中间量。
5. 复用地形、策略、价值和回合曲线，但验证含义是否仍成立。
6. 只有实现、测试和观察证据全部接通后，才把状态改为 `active`。

通用经验回放位于 `src/rl/replay-buffer.ts`。离散 DQN 与连续 TD3 复用这一实现；环境专属 action 类型通过泛型表达，不再复制容量、抽样和克隆逻辑。

## 连续控制与共享策略实验

面向 TD3、PPO、SAC 等连续控制实验时，仍保留“环境 → 策略 → 更新 → 证据”四层，但增加以下约束：

- 物理坐标必须有明确单位。总览、碰撞、雷达、相机和奖励距离使用同一米制世界；UI 缩放不得改变训练尺度。
- 连续方向盘与踏板必须由原生连续策略输出，不能用少量离散组合伪装。动作边界、比例响应、探索噪声和推理去噪都要有测试。
- 雷达采用固定角度网格和独立语义距离通道；同一扇区中的道路边缘、车辆、结构物与目的地不得互相覆盖。神经网络读取固定长度网格，人类观察层读取带米数与方位的检测列表。
- 训练吞吐与观察刷新解耦。环境和网络更新放在 Worker，`MAX` 模式按浏览器可用算力批量推进；主线程仅用 RAF 消费最新快照。
- 连续任务不以单次到达为训练终点。到站后保留模型、Replay 和全局步数，只轮换新的有效起终点。
- 多 actor 共享一个策略时，只允许当前 learner 写入 Replay 和更新权重；其余 actor 使用最新权重推理，并按固定环境步公平轮换 learner。
- 任一时刻只有一个 learner，但所有交通车都在全车队轮换范围内。其他车不是装饰性观察者，而是可感知、可碰撞的动态环境。动态扩缩容不得重建模型、Replay 或全局步数。
- 交通路线必须有方向和车道语义。双向车流使用分离的右侧车道中心线；单行道与环岛不得逆向导航。车车碰撞应基于车身朝向与尺寸，不能用会误伤相邻车道的大圆简化。
- 驾驶视角必须从同一条规划路线投影，不允许用固定直路冒充弯道、环岛或岔路。
- 动态交互必须成为训练事件：车辆碰撞要产生明确的大惩罚、事故占道时间、恢复条件和远离其他车辆的有效重生点。

### 城市地图质量门槛

正式地图应来自有出处的真实路网或通过同等级验证的生成器。每张地图至少验证：最大连通分量、可达目的地、真实等比例坐标、死胡同或绕行结构、道路宽度、署名来源。随机生成器没有这些质量门槛时，优先使用多张固定且可复现的真实城区。

### 连续控制验收证据

1. 单元测试：连续动作比例与裁剪、多通道雷达形状、TD3 延迟 actor 更新、到站换单、碰撞惩罚、堵塞计时、分散重生、推理冻结 Replay。
2. 吞吐证据：MAX 模式下环境步持续增长，RAF 帧率改变不改变训练语义。
3. 公平性证据：超过轮换阈值后 learner 身份变化，且只有一个 actor 贡献训练 transition。
4. 视觉证据：桌面和窄屏均检查总览比例、局部雷达长度、路线透视、车辆可辨识度和控制区溢出。

## 奖励设计方法

奖励应形成可解释的有序梯度，而不是随意放大数字：

```text
到达目标 > 普通移动 > 代价地形 > 无效动作 > 灾难事件
```

当前地图使用 `+30 / -1 / -3 / -4 / -60`。边界与墙体的 `-4` 比普通移动和泥地更差，足以教会智能体避免无效动作；又远小于悬崖的 `-60`，不会让所有负面事件看起来相同。修改地图尺寸或最短路径后，应重新检查成功回报是否仍能抵消合理路径长度。

连续任务还必须做“不作为基线”审计：对整个超时窗口累加原地不动的回报，与正常探索的碰撞、越界和进度回报比较。如果不作为更划算，优先对“无新进展”扣分，而不是直接奖励车速；同时设置有语义的 `stalled` 终止事件，提前重启无效回合，防止高速训练在大量空步上浪费时间。

## 质量门槛

- 环境：每种地形、边界、墙体、悬崖和目标都有确定性测试。
- 算法：终止状态不错误引入 bootstrap，所有 Q 值保持有限数。
- 教学：每个数值都能追溯到一次 transition，不用颜色作为唯一信息。
- 观察：至少覆盖单步、当前回合和跨回合三种时间尺度。
- 视觉：遵循 `design.md`，主画布最高权重，精确数值不拥挤进地图格。
- 性能：训练循环不得依赖 React 渲染；路径计算和真实地图解析应缓存或在构建阶段完成。
- 诚实性：规划中的算法不得显示为可运行或已验证。
