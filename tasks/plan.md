# Implementation Plan: 障碍物自动驾驶训练实验

> 2026-10-10 状态说明：下面保留的是最初 V1 计划，便于追溯决策；当前产品已经按用户反馈升级为 V2 共享出租车队。V2 已移除手动/脚本模式，采用 3 张固定真实路网、连续订单、4/10/20 车共享 DQN、learner 轮换、碰撞恢复、Worker MAX 训练、RAF 节流、米制可缩放总览和最多 4 个独立 Three.js 驾驶相机。尚未声称“策略已收敛”或达到真实道路安全门槛；这需要独立的长时训练与固定评估集报告。

## Overview

在现有 RL Navigation Lab 中新增一个独立的“障碍驾驶”课程。它是浏览器内的 2D 教学仿真，不代表真实道路自动驾驶能力或安全认证。第一版使用离散控制的 DQN，让学习者观察车辆如何从距离传感器、速度和道路偏差中学习车道保持、绕开静态障碍并抵达终点；连续控制的 PPO 和动态交通只进入后续阶段。

核心学习问题：**DQN 如何把传感器观测映射成九个驾驶动作的 Q 值，并通过 replay buffer 与 target network 学会避障？**

## Scope

### V1 必须包含

- 2D 俯视道路、车辆、道路边界、检查点和静态障碍物
- 运动学自行车模型的简化版，固定时间步，结果可由随机种子复现
- 5 条距离射线、车速、航向误差、横向偏差、路线进度和上一动作组成的数值观测
- 9 个离散动作：转向 `左 / 中 / 右` × 加速度 `制动 / 保持 / 加速`
- 手动驾驶、脚本基线、训练和纯评估四种模式
- TensorFlow.js DQN、经验回放、target network 和 Web Worker 训练
- 单步奖励分解、动作 Q 值、传感器、replay 样本和跨回合指标
- 固定种子评估集与未见种子泛化集

### V1 不包含

- 摄像头图像输入、CNN、真实道路数据或真实车辆控制
- 行人、交通灯、多车博弈和动态障碍物
- 连续方向盘控制和 PPO
- 对现实自动驾驶安全性、合规性或可部署性的任何声明

## Environment Contract

### World

- 逻辑画布：`960 × 640`，渲染尺寸自适应
- 道路由中心线、左右边界和有序检查点描述，不绑定像素截图
- V1 提供 3 条固定教学路线和种子化随机障碍生成器
- 单回合最多 600 个 `100ms` 仿真步
- 碰撞、驶离道路超过容忍时间、到达终点或超过步数结束回合

### Observation vector

所有数值归一化到 `[-1, 1]` 或 `[0, 1]`：

1. 左 60° 距离
2. 左 30° 距离
3. 正前方距离
4. 右 30° 距离
5. 右 60° 距离
6. 当前速度
7. 航向误差的正弦
8. 航向误差的余弦
9. 相对车道宽度归一化后的横向偏差
10. 当前检查点区间内的路线进度
11. 上一步转向量
12. 上一步加速度量

不把绝对屏幕坐标直接交给智能体，避免记住固定地图位置。

### Action space

动作编号由转向和加速度的笛卡尔积形成，共 9 个动作。动作元数据必须同时提供机器值和中文标签，训练事件记录选择来源为探索或利用。

## Reward Design

奖励必须从同一次环境 transition 产出，并展示逐项分解：

| 奖励项 | 建议值 | 目的 |
| --- | ---: | --- |
| 路线进度 | `2.0 × Δprogress`，裁剪到 `[-1, 1]` | 奖励真正向目标前进 |
| 通过检查点 | `+3` | 提供稀疏的阶段成功信号 |
| 抵达终点 | `+30` | 明确完成目标 |
| 每步成本 | `-0.02` | 避免无限绕行或静止 |
| 横向偏差 | `-0.03 × abs(offset)` | 温和鼓励保持车道 |
| 危险距离 | 最近射线 `< 0.15` 时最多 `-0.20` | 在碰撞前形成安全余量 |
| 转向突变 | `-0.05 × abs(Δsteer)` | 减少左右抖动 |
| 倒退 | `-0.20` | 防止靠反复倒车刷状态 |
| 驶离道路 | 每步 `-1.5`，连续 8 步终止 | 允许短暂修正但阻止越界行驶 |
| 碰撞 | `-25` 并终止 | 明确灾难事件 |

防奖励作弊规则：速度本身不提供正奖励；只有路线进度增加时才获得正向 shaping；检查点只能按顺序且每回合奖励一次；重访区域不能重复领取奖励。

## Algorithm Decision

V1 使用 DQN，而不是把连续道路强行塞入 Q 表：

- 网络：`12 → 128 ReLU → 128 ReLU → 9`
- 优化器：Adam，初始学习率 `0.0005`
- 损失：Huber loss，梯度裁剪
- 折扣率：`0.99`
- replay buffer：50,000，warm-up 1,000，batch 64
- target network：每 500 次更新硬同步
- epsilon：从 `1.0` 线性衰减到 `0.05`，跨度 30,000 环境步
- 训练运行在 Web Worker；主线程只接收节流后的观察事件
- 所有权重导入导出必须包含环境版本、观测顺序和动作映射

后续路线：Double DQN 用于降低过估计；Prioritized Replay 用于观察样本优先级；PPO 用于连续转向与油门；动态障碍物在静态障碍泛化通过后再引入。

## Curriculum

1. **L0 手动基线**：无学习，验证车辆运动、传感器和奖励解释。
2. **L1 车道保持**：直道、无障碍，学习稳定前进与方向修正。
3. **L2 固定避障**：三张固定地图，每张 1 至 3 个障碍物。
4. **L3 随机静态障碍**：位置、大小和起点带种子变化，要求泛化。
5. **L4 动态交通**：规划项，只有 L3 验收通过后才能开始。

课程升级依据评估指标，不依据单次高回报。每一层保存独立训练配置和固定评估种子。

## Observation and Teaching UI

保持 `design.md` 的科学仪器风格与琥珀色强调：

- 主画布：道路、车辆、障碍、目标路线和当前轨迹
- 观察层：传感器射线、危险距离、路线进度、动作 Q 值，可独立切换
- 单步面板：12 维 observation、9 个动作 Q 值、动作来源、逐项奖励、done 原因
- 训练面板：loss、epsilon、buffer size、target sync age、训练步数
- 回合证据：成功率、碰撞率、驶离道路率、平均回报、路线效率、最小安全距离
- replay 检查器：抽取一条样本，展示 `s / a / r / s' / done` 与 TD error
- 评估模式：冻结网络和 epsilon，使用固定种子，不写入 replay buffer

原型必须先明确桌面和移动端布局、观察层及交互状态，再进入前端实现。

## Architecture Decisions

- 新增通用 `EnvironmentAdapter<Observation, Action, Event>`，让 Q-learning 地图和驾驶环境共享调度与证据流，但不共享不合适的 Q 表结构。
- 将现有 `LearningStrategy` 扩展成 tabular 与 neural 两种策略适配器；DQN signals 至少包含 `predictedQValues`、`targetQ`、`tdError`、`loss`、`bufferSize`、`targetSyncAge`。
- 物理环境保持纯 TypeScript 和确定性；渲染层不负责碰撞判定或奖励计算。
- 训练 Worker 与 UI 通过有版本的消息协议交互；高速训练时事件采样不得改变训练本身。
- 训练配置、模型权重和评估报告分别序列化，不能把一次本地演示称为模型质量验收。

## Evaluation Gates

使用 20 个固定评估种子和 20 个训练中未出现的泛化种子：

| 指标 | 固定评估集 | 未见种子集 |
| --- | ---: | ---: |
| 到达终点率 | `≥ 90%` | `≥ 80%` |
| 碰撞率 | `≤ 5%` | `≤ 10%` |
| 驶离道路终止率 | `≤ 5%` | `≤ 10%` |
| 中位路线效率 | `≤ 1.35` | `≤ 1.50` |
| 停滞回合率 | `≤ 5%` | `≤ 10%` |

路线效率定义为“实际前进弧长 / 基准路线弧长”。所有指标同时报告样本数；训练回报不能替代评估结果。

## Dependency Graph

```text
环境与证据泛型契约
    ├── 确定性车辆环境与奖励
    │       ├── 手动/脚本基线
    │       └── 固定种子评估器
    ├── DQN 策略与 Worker 协议
    │       └── 训练、保存和纯评估
    └── 自主审核后的交互原型
            └── 驾驶画布与观察面板
                    └── 端到端课程与浏览器验收
```

## Risks and Mitigations

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 奖励作弊，例如原地抖动刷分 | 高 | 仅奖励路线进度，检查点单次领取，增加停滞检测 |
| 浏览器训练卡顿 | 高 | Worker 训练、节流事件、限制网络规模和 replay 拷贝 |
| 观测维度或动作映射悄然变化 | 高 | 消息、模型和评估报告带 schema version，并做兼容校验 |
| 固定地图过拟合 | 高 | 从 L2 进入 L3 前引入种子随机化和未见种子评估 |
| 物理仿真过度复杂 | 中 | V1 固定时间步、简化自行车模型、无动态交通 |
| 指标好看但驾驶不安全 | 高 | 分开报告成功、碰撞、越界、效率和安全距离 |
| 新课程破坏现有 Q-learning | 中 | 适配器隔离，保留全部现有回归测试 |

## Open Decisions for Implementation

这些不是当前规划的阻塞项，实施时通过原型和基准测试收敛：

- 三条教学路线的具体几何和障碍布局
- 射线最大距离与车辆碰撞盒尺寸
- 高速训练每隔多少环境步向 UI 发布一次快照
- L1 到 L2 的自动升级阈值是否与最终评估阈值相同
